### 사용자 답변으로 확정된 차이

1. 소수 둘째 자리 폴백 대신 **입력된 유한 소수를 기약분수로** 쓴다. `1.3028 → 3257/2500`. 인식 우선순위는 정수 → 분모 64 이하 분수 → π의 배수 → e의 배수 → 제곱근을 유지한다. 여기에 해당하지 않는 값은 십진 문자열을 BigInt 유리수로 약분한다. 따라서 모든 유한 숫자의 `isExact`는 true이며, `1.3028` 자동 라벨을 오류로 처리하던 명세 예시는 대체된다. 이것은 입력 소수를 정확히 표현한 것이지, 그 소수의 원래 무리수를 추정한 것이 아니다.
2. 실제 UI에서 빠져 있던 판별식 표시를 파라미터 패널에 복원했다. 계수·판별식을 Rational로 끝까지 계산하고 결과를 KaTeX로 표시한다.

`evaluate.ts`의 기존 `numeric`을 재사용해 sqrt/pi/e를 평가한다. 기존 `evaluate`는 유리수 다항식만 지원하므로 그대로 호출하면 sqrt/pi를 거부한다. 수식 AST를 먼저 검사해 변수(e 상수 제외), 관계식, sqrt 이외 함수 및 거듭제곱을 금지한다. 렌더러에는 종전처럼 number를 전달한다. `e`는 이 입력 경로에서만 자연상수로 평가하며 공통 채점기를 변경하지 않았다.

점의 원래 식은 `x_tex`/`y_tex`에 보존하고 재파싱해도 유지한다. graph/slider 초기 점과 point 액션 모두 지원한다. 칠판 좌표·화살표 끝·구간·양의 반지름, 파라미터 범위/간격/초깃값에도 같은 상수식 검사를 적용한다.
