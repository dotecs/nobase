# 학생 학습 화면 UI 개선 — 개발 명세서 (U-0 ~ U-6)

- 작성일: 2026-10-28
- 대상: Codex(`nobase` 레포, main `9694aa3` 이후 기준)
- 브랜치: `feat/learn-ui-v1` → main 끝에서 분기, 항목당 커밋 1개, 검수는 Claude, 머지·배포는 Claude
- 범위: **학생 화면만** — `/learn`(홈), `/learn/diagnostic`, `/learn/session/[id]`(학습·복습), `/learn/review`, 세션 완료 화면. 관리자·코치 화면은 범위 밖.
- 새 의존성 **없음**. 디자인 토큰은 `styles/globals.css`의 기존 값만 사용(새 토큰 추가 금지). 공용 컴포넌트는 `@/components`의 `Header`, `Button`을 사용.

> `[확인]` = 대표 확인 필요 항목. 그 외 수치는 이 문서가 기준이며, 바꾸려면 문서를 먼저 고친다.

## 0. 한 장 요약

| 항목 | 결정 |
|---|---|
| 목적 | 파일럿 학생(3기 1~2명)이 **설명 없이** 혼자 진단 → 학습 → 복습을 끝낼 수 있게. "지금 뭘 해야 하는지"와 "어디까지 왔는지"가 매 화면 첫눈에 보이게 |
| 동작 변경 | **없음**. 서버 액션·규칙·DTO·DB는 손대지 않는다. 화면 구조·문구·스타일·상태 표시만 바꾼다 |
| 기준 기기 | **모바일 우선(360~430px)**. 학생은 폰으로 풀이 사진을 찍는다. 데스크톱은 폭만 넓어진다 |
| 테마 | 사이트 공통 다크/라이트(`[data-theme]`, `prefers-color-scheme`) 그대로. 글래스 스타일은 적용하지 않는다(공개 페이지 전용) |
| 헤더 | 홈·복습 목록은 사이트 `Header` 사용. **진단·세션 화면은 집중 모드**: 사이트 헤더 대신 얇은 상단 바(홈 링크 · 진행 · 타이머) |
| 접근성 | 터치 타깃 44px 이상, 포커스 링 유지, `role="status"`/`aria-live`로 피드백 읽기, 색만으로 정오답을 구분하지 않음(아이콘+문구) |
| 성능 | 클라이언트 번들 증가 없음(아이콘은 인라인 SVG 6개 이하). 새 이미지 자산 없음 |

## 1. 원칙과 제약

1. **코드 경계**: 수정 대상은 `app/(main)/learn/**`, `components/learn/**`, `lib/learn/home-summary.ts`(표시용 파생값 추가만). `lib/learn/*-runtime.ts`, `rules/`, `actions.ts`의 **시그니처·반환값을 바꾸지 않는다**. 화면이 더 필요한 값은 이미 내려오는 값에서 파생하거나, `home-summary.ts`에 순수 함수로 추가한다.
2. **토큰만 사용**: 색은 `--color-*`, 간격 `--space-*`, 글자 `--text-*`·`--font-*`, 모서리 `--radius-*`, 그림자 `--shadow-*`. 하드코딩 색(`#0072c6` 등) 0건. 현재 `learn.module.css`·`input.module.css`의 하드코딩은 전부 제거.
3. **다크 모드**: 토큰을 쓰면 자동. 직접 색을 쓰는 곳이 생기면 라이트·다크 둘 다 정의.
4. **문구**: 학생 대상 존댓말, 한 문장, 전문용어 금지("소주제"→"주제", "검증"→"완료", "needs_repair" 같은 내부 상태 노출 금지). 숫자는 항상 단위와 함께("3문항", "15분").
5. **테스트**: 화면 컴포넌트는 `renderToStaticMarkup` 기반 기존 패턴(`lib/learn/session-page.test.tsx`, `input.test.tsx`)으로 **상태별 1개씩** 스냅샷 아닌 문구·역할 검사. 동작 로직 테스트는 기존 것 그대로 통과해야 한다.
6. **금지**: 진단 중 정오답 표시(규칙), 정답·부등호·answer_spec을 클라이언트에 내리는 변경, 세션 중 사이트 헤더의 다른 페이지 링크 노출(집중 모드), 애니메이션 라이브러리.

## 2. 공통 레이아웃 (U-0)

### 2.1 페이지 틀
- 홈·복습 목록: `Header`(기존) + `main.page` — 폭 `min(100% - 32px, 720px)`, 상단 여백 `--space-6`(모바일) / `--space-10`(데스크톱).
- 진단·세션: **집중 모드 틀** `FocusShell`(신규, `components/learn/FocusShell.tsx`)
  - 상단 바(높이 48px, sticky): 왼쪽 "← 학습 홈"(링크, 세션 중에는 `[확인]` 없이 그대로 이동 허용 — 세션은 서버에 남아 "이어하기"로 복귀), 가운데 진행 표시(아래 2.3), 오른쪽 타이머(아래 2.4).
  - 본문 폭 `min(100% - 32px, 640px)`.
  - 사이트 헤더·푸터 없음.

### 2.2 카드
- `.card`: 배경 `--color-surface`, 테두리 `1px solid --color-border`, 모서리 `--radius-xl`, 그림자 `--shadow-sm`, 패딩 `--space-5`(모바일) / `--space-6`.
- 카드 안 제목은 `h2`, `--text-lg`, `--font-semibold`. 카드 간격 `--space-4`.

### 2.3 진행 표시
- 세션: 상단 바 가운데에 **점 진행(dots)** — 문항 수만큼 작은 원(8px), 완료는 `--color-primary`, 현재는 테두리 강조, 남은 것은 `--color-border`. 8개 초과면 텍스트 `3 / 12`로 대체. `aria-label="문항 3 / 8"`.
- 진단: 문항 수가 가변(후속 문항)이라 점 대신 텍스트 `문항 3`만. 전체 개수 표시 금지(후속 여부가 드러남).

### 2.4 타이머
- 상단 바 오른쪽, `mm:ss`, 등폭 숫자(`font-variant-numeric: tabular-nums`).
- 남은 시간 2분 이하: 색 `--color-warning`, 30초 이하: `--color-error` + 1초 간격 점멸 금지(깜빡임 대신 색만). `aria-live="polite"`로 2분·30초 시점에 한 번씩만 읽기("2분 남았습니다").
- 0이 되면 기존 만료 로직 그대로. 만료 후 화면은 U-4.

### 2.5 버튼
- 주 버튼은 `@/components` `Button`(`variant="primary" size="lg" fullWidth`). 보조는 `variant="outline"`. `learn.module.css`의 자체 `.button` 삭제.
- 제출 버튼은 입력이 비었거나 사진(필수)이 없으면 `disabled`, 그 이유를 버튼 아래 작은 글씨로("풀이 사진을 올리면 제출할 수 있어요").

## 3. 화면별 명세

### U-1 학습 홈 `/learn`
학습자 상태 4종 + 접근 불가. 각 상태에서 **첫 카드가 "지금 할 일" 하나**여야 한다.

| 상태 | 첫 카드(할 일) | 그 아래 |
|---|---|---|
| `diagnostic_pending` | 제목 "출발점 진단", 본문 "약 {minutes}분 · 6문항 안팎 · 정답은 알려주지 않아요"(사진 필수면 "풀이 사진이 필요해요" 추가), 버튼 "진단 시작" | 진단이 왜 필요한지 2줄 안내 카드 |
| `diagnostic_in_progress` | 제목 "진단을 이어서 풀어요", 버튼 "이어하기" | 없음 |
| `awaiting_coach` | 제목 "코치가 결과를 보고 있어요", 본문 "확인이 끝나면 여기서 학습을 시작할 수 있어요", 버튼 없음 | 없음 |
| `active` | 제목 "오늘의 학습", 본문 "{items_per_session}문항 · 약 {max_minutes}분", 버튼 "학습 시작". 복습이 있으면 그 **위에** 복습 배너(아래) | 목표 카드, 주제 지도, 최근 활동 |
| 그 외(`paused` 등) | "학습이 잠시 멈춰 있어요. 코치에게 문의해 주세요." | 없음 |

- **복습 배너**(`due > 0`일 때만): 주의색 배경(`--color-warning-50` / 다크는 `--color-warning-700` 15% 불투명), 문구 "오늘 복습 {due}개가 기다리고 있어요", 버튼 "복습 먼저 하기"(→ `/learn/review`). 복습을 먼저 권하되 학습 시작을 막지 않는다.
- **목표 카드**: 제목 = 목표명, 큰 숫자 `{done} / {total}` + "완료한 주제", `progress`, 아래 한 줄 "완료 {verified} · 유지 {retained}". 100%면 문구 "목표를 모두 달성했어요" + 배지.
- **주제 지도**(기존 "단원별 진행" 대체): 단원별 한 줄 — 단원명, 소주제 점(dots) `completed/total`. 점 색: 완료(verified/retained) `--color-success`, 학습 중/보완 필요 `--color-primary`, 미확인 `--color-border`. 점에 `title`로 주제명. `home-summary.ts`에 단원별 `abilities: {id,name,state}[]`를 **추가**(기존 필드 유지).
- **최근 7일 활동**: 7칸 막대(높이는 제출 수 비례, 최대값 기준), 날짜는 요일 한 글자(월·화…), 막대 아래 숫자. 0이면 막대 없이 점선.
- 홈은 서버 컴포넌트 유지. 새 클라이언트 컴포넌트 추가 금지(버튼 2개는 기존 `StartDiagnostic`·`StartSession`).

### U-2 진단 `/learn/diagnostic`
- `FocusShell` 사용. 시작 직후 첫 문항 위에 **1회성 안내 카드**(세션 상태 `planIndex===0`일 때만): "정답은 진단이 끝난 뒤 코치가 알려드려요 · 모르면 비워 두지 말고 제출해 주세요". 닫기 버튼 없음(첫 제출과 함께 사라짐).
- 문항 카드: 지문(`--text-xl`, 수식은 기존 렌더러), 답 입력(U-6), 사진(U-6), 제출 버튼.
- 제출 중: 버튼 "저장 중…" + 입력 비활성(기존). 제출 성공 시 다음 문항으로 **카드 교체**(기존 `key` 리마운트 유지).
- 완료 화면(`view.complete`): 체크 아이콘 + "진단을 마쳤어요" + "코치가 확인하면 학습 홈에서 시작할 수 있어요" + 버튼 "학습 홈으로".
- 세션 없음(`!view`): "학습 홈에서 진단을 시작해 주세요" + 버튼.

### U-3 학습·복습 세션 `/learn/session/[id]`
- `FocusShell` 사용. 제목은 `kind`에 따라 "오늘의 학습" / "오늘의 복습"(기존 로직).
- **피드백 패널**(`FeedbackPanel` 재작성, `components/learn/FeedbackPanel.tsx`로 이동):
  - 4상태 — 정답(초록, 체크 아이콘, "정답이에요"), 도움 정답(초록 옅게, "도움을 받아 맞혔어요"), 오답·재시도 가능(주황, "다시 확인해 보세요 · 한 번 더 풀 수 있어요"), 오답·정답 공개(빨강 옅게, "정답: …" + 해설), 코치 확인 대기(파랑, "코치가 풀이를 확인해요").
  - 패널은 문항 카드 **위**에, `role="status"`. 힌트·해설은 접힘 없이 그대로 표시.
  - 이전 문항 피드백과 현재 문항이 섞이지 않게: 패널에 "이전 문항" 캡션을 붙인다(피드백은 직전 제출 결과이므로).
- 문항 카드: U-2와 동일 구성. 재시도 상태면 입력 위에 "다시 풀기" 라벨.
- **힌트**: 현재 UI에 힌트 요청 버튼이 없다. 규칙은 `max_hints_per_item`을 갖지만 런타임에 힌트 요청 액션이 **없으므로 이번 범위에서 만들지 않는다**(Phase 3 과제로 명세 하단에 기록).
- 완료 화면(U-4).

### U-4 세션 완료
- 큰 숫자 셋: "정답 {correct}" · "새로 완료한 주제 {newly_verified.length}" · "다음 복습 {date 또는 '예정 없음'}". `timed_out`이면 제목 "오늘은 여기까지" + "시간이 다 됐어요. 푼 만큼은 저장됐어요".
- 새로 완료한 주제가 있으면 주제명 목록(배지). `newly_verified`는 id 배열이므로 이름은 서버 페이지에서 팩 데이터로 치환(`learningView`가 이미 팩을 들고 있지 않으면 `learn_abilities` 조회 1회 추가 — **런타임 시그니처 변경 금지**, 페이지에서 조회).
- 버튼 "학습 홈으로"(primary). 복습이 남아 있으면 보조 버튼 "복습 하러 가기".

### U-5 복습 목록 `/learn/review`
- `Header` + 카드 하나: 제목 "오늘의 복습", 주제 목록은 `id · 이름` 대신 **이름만**(id는 학생에게 의미 없음), 각 항목에 "완료한 날 기준 +1일/+3일/+7일" 같은 간격 설명은 넣지 않는다(혼란). 버튼 "복습 시작"(primary). 0개면 "오늘은 복습이 없어요" + "학습 홈으로".

### U-6 입력 컴포넌트 (`components/learn/*`)
- **AnswerInput**
  - 키패드: 4열 → `7 8 9 ⌫` / `4 5 6 −` / `1 2 3 /` / `0 . ␣`(공백 대신 빈칸). **지우기(⌫) 키 추가**(한 글자 삭제, 길게 누르면 전체 삭제는 하지 않음). 키 높이 48px, 간격 `--space-2`.
  - 입력창은 키패드 위, 큰 글자(`--text-xl`), `inputMode` 기존 유지. 미리보기는 입력창 바로 아래 작은 글씨("보이는 식: …"), 기존 렌더링 로직 유지.
  - 부등호 선택(기존 `relation_required`): 4개 버튼을 **가로 한 줄**(각 25%), 선택 상태는 채움색. 라벨 "부등호를 고르세요".
  - 선택형: 보기 버튼 전체 폭, 선택 시 채움색 + 체크 아이콘.
  - 서술형·사진 풀이: 텍스트 영역 최소 4줄.
- **PhotoCapture**
  - 버튼 하나 "사진 찍기 / 올리기"(카메라 아이콘, outline), 파일 input은 숨김(label로 연결). 선택 후 썸네일(최대 160px) + "다시 찍기" 버튼 + 업로드 상태("올리는 중…" / "올렸어요" 체크).
  - 필수인데 없으면 제출 버튼 아래 안내(2.5).
- **FeedbackPanel**: U-3 참조.
- `input.module.css`도 토큰으로 교체.

## 8. 입력 문법·미리보기 (수식 입력 v2, 2026-10-29)

**보이는 식 = 채점기가 해석한 식.** 입력 문자열을 KaTeX에 직접 전달하지 않고 `parseMath`의 AST를 `toLatex`로 바꿔 표시한다. 예를 들어 `1/2x`와 `(1/2)x`는 모두 세로 분수 ½ 뒤에 x가 곱해진 모습이다. 분모 전체를 2x로 쓰려면 `1/(2x)`를 입력한다. `0.50` 같은 원래 숫자 표기도 유지한다.

| 종류 | 지원 입력 | 표시·해석 |
|---|---|---|
| 기본 연산 | `+ - * / ^`, `− × ÷`, `² ³` | 분수는 세로로, 지수는 위첨자로 표시. `-x^2`는 `-(x^2)` |
| 관계식 | `x=7`, `x<=-7`, `x≥2` | 답 입력 한 칸에 전체 식을 그대로 입력. 방정식 문항은 기존처럼 숫자만 입력 가능, 부등식은 관계 기호 필요 |
| 근호·절댓값 | `sqrt(2)`, `√2`, `root(3,8)`, `abs(x)`, `|x-1|` | 루트와 절댓값으로 표시. 절댓값 막대 중첩은 지원하지 않음 |
| 상수 | `pi`, `π`, `2pi` | π. `e`는 기존 한 글자 변수이며 자연지수는 `exp()` 사용 |
| 로그·지수 | `log(x)`, `log(2,8)`, `ln(x)`, `exp(x)` | 상용로그·밑 2 로그·자연로그·자연지수 |
| 삼각함수 | `sin(x)`, `cos(x)`, `tan(x)`, `sin(30°)` | 기본 라디안. 도 단위는 명시적인 `°`만 사용 |
| 지문용 LaTeX | `\frac`, `\dfrac`, `\tfrac`, `\sqrt`, `\sqrt[n]`, `\pi`, `\log_b`, `\ln`, `\sin`, `\cos`, `\tan`, `\left|…\right|`, `^{\circ}` | 파서 정규화를 거쳐 같은 AST와 표시 사용 |

함수 괄호를 생략하면 다음 원자 하나만 인수다. `sqrt2x`는 `sqrt(2)*x`, `sin 2x`는 `sin(2)*x`이며, 미리보기도 그 곱셈을 구분해 표시한다. `xy`는 두 변수의 곱, `pix`는 π와 x의 곱이다.

미지원: `∫`, `∑`·`Σ`, `lim`·`→`, 행렬, 알 수 없는 LaTeX 명령. `e` 상수, 각도 단위 자동 추론, 근호의 특정 간단한 형태 강제는 이번 범위에 포함하지 않는다.

- 해석 성공: “보이는 식:”과 실제 수학 표기를 표시한다. 입력·풀이 줄·패드·피드백·코치 타임라인이 같은 AST 변환기를 쓴다.
- 미지원 기호: 기호 이름을 포함한 안내만 `aria-live="polite"`로 읽는다. 마지막 성공 표시는 흐리게 유지한다.
- 미완성(`5/`, `sqrt(`, `x<=`): 마지막 성공 표시를 흐리게 유지하고 원문을 함께 보여 준다. 풀이 줄은 성공한 미리보기만 표시한다. 읽기 전용 피드백·코치 화면은 실패 시 원문만 표시한다.
- 제출: 빈 답만 막는다(필수 사진 등 기존 조건 유지). 미지원·미완성 식은 서버가 확인하고 한국어 안내를 반환한다.
- 키패드: 숫자·기호·함수 3페이지. 풀이 줄과 답 입력 중 포커스된 곳에 삽입한다. `|x|`는 `||`와 가운데 커서를 넣는다. 답 입력의 관계 키는 문항 속성에 따르고, 풀이 줄에서는 관계 기호를 사용할 수 있다.
- 접기 상태는 `learn.keypad.collapsed`에 저장한다. 패드는 항상 펼친다. 입력 도움말은 접이식으로 제공한다.
- 채점은 기존 유리수 다항식의 정확 계산이 우선이다. 지원 범위 밖인 정확 계산만 수치 비교로 넘어간다(기본 상대오차 1e-9, 공통 유한 표본점 최소 6개; 상수는 1개). 정의역 표본이 부족하면 코치 확인으로 보낸다. 문항의 명시적 허용 오차는 우선한다.
- 입력 상한 4,000자, 토큰 상한 600개, 재귀 깊이 40을 유지한다. 서버·클라이언트가 같은 파서를 사용한다.
- `LearnItem`·`StudentItem` DTO와 공통 타입은 변경하지 않는다. 2026-10-29 대표 승인 예외로 `answer_spec`의 `number.value`·`fraction.value`는 기존 유리수 검증을 유지하면서 변수 없는 유한 상수식(`2sqrt(3)`, `pi/4`)도 허용한다. 저장 형식은 문자열 그대로다.
