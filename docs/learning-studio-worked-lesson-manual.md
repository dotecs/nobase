# 문제풀이 강의 제작 매뉴얼 (v1, 2026-11-13 대표 기획 의도)

개념 강의는 `learning-studio-lesson-production-manual.md`를 따른다. 이 문서는 `kind:"worked"` 강의에만 적용하고, 두 문서가 다르면 문제풀이 강의에서는 이 문서가 우선한다. 지시(chalk)·TTS·자막·모바일 규칙은 개념 강의 매뉴얼 3·4·8·9장을 그대로 쓴다.

## 0. 한 문장으로

> **이 문제를 잘 푸는 사람은, 풀면서 무슨 생각을 하는가**를 보여 준다.

개념을 다시 가르치는 강의가 아니다. 학습자는 숙련자의 시험지를 어깨 너머로 보면서, 그 사람이 속으로 하는 말을 듣는다. 화면은 **시험지**, 음성은 **그 사람의 머릿속**이다.

가장 중요한 부분은 **첫 줄을 적기 전**이다. 숙련자는 펜을 들기 전에 암산으로 식을 이리저리 바꿔 보고, 어디서 시작할지를 정한다. 원본 풀이에는 이 과정이 적혀 있지 않다. 이 강의가 존재하는 이유는 그 적히지 않은 부분을 말로 꺼내 주는 것이다.

## 1. 화면: 시험지 지면

시험지에서 문제를 푸는 모습과 같아야 한다.

1. **문제는 화면 맨 위에 처음부터 끝까지 나와 있다.** 풀이가 진행되는 동안 사라지거나 다른 화면으로 바뀌지 않는다. 숙련자는 풀다가 문제를 다시 올려다본다. 학습자도 그럴 수 있어야 한다.
2. **풀이는 문제 아래로 한 줄씩 적혀 내려간다.** 위에서 아래로만 쌓인다. 지나간 줄은 지우거나 접지 않는다.
3. **마지막 줄은 답이다.** 답을 적고 표시한다(∴, 밑줄). 답이 문제가 요구한 꼴(값, 범위, 식)인지는 3장의 "올려다보기"에서 말로 확인한다.
4. **여백 메모는 실제로 시험지에 할 만한 것만.** 문제 문장의 표현에 밑줄, 그 옆의 짧은 손글씨(`→ D=0`), 약식 그래프. 숙련자가 시험지에 하지 않을 것(개념 정리 표, 공식 모음, 번역 흐름도)은 올리지 않는다.
5. **그림은 여백의 약식 그림 수준으로.** 그래프나 수직선이 풀이의 일부일 때(부등식의 해 읽기 등)만 풀이 옆이나 아래에 그린다. 축 눈금까지 정확한 그래프는 숙련자가 그리지 않으므로 쓰지 않는다. 답을 확인하는 정밀한 그래프가 필요하면 풀이가 끝난 뒤의 장면에 둔다.

### 금지

- 문제를 보여 주는 장면과 풀이 장면을 따로 두는 것. 장면이 넘어가면 문제가 사라진다.
- 풀이 전에 "번역 흐름도"(chain)나 개념 정리를 한 화면 가득 보여 주는 것.
- 풀이 줄을 한꺼번에 보여 주는 것. 줄은 말과 함께 한 줄씩 나타난다.

### 무대 구성

풀이 전체를 **한 장면**에 둔다(문제 읽기부터 답까지). 장면을 나누면 지면이 끊긴다. 풀이 뒤에 붙는 장면은 변형 문제(quiz) 하나뿐이고, 정밀 그래프로 답을 확인할 필요가 있을 때만 그 앞에 확인 장면을 하나 더 둔다.

| 지면 요소 | 무대에서 |
|---|---|
| 문제 | `steps` 무대의 `problem` (맨 위 고정) |
| 풀이 줄 | `steps` 무대의 `steps[]`, 문장의 `cue.step`으로 한 줄씩 |
| 여백 메모·밑줄 | `items`(손글씨) + `draw`/`label` 지시 |
| 답 표시 | 마지막 줄의 답 부분(`\p{ans}{…}`)에 `underline`, `until:"scene"` |
| 암산으로 스쳐 가는 식 | 오른쪽 여백의 손글씨, `until:"sentence"` (아래 "암산 메모") |

### 문제 칸 쓰는 법 (2026-11-13 추가)

`steps` 무대에 `problem`을 적으면 문제가 풀이 줄 위에 장면 내내 고정된다. 아직 적지 않은 줄의 자리는 처음부터 비워 두므로, 줄이 늘어나도 문제와 앞줄이 움직이지 않는다. 세로 화면(모바일)에서는 문제가 위에 붙어 있고 풀이만 스크롤된다.

```json
"stage": {
  "type": "steps",
  "problem": "이차함수 $y=\\p{q}{x^2-2x}+a$ 의 그래프를 [[move|$y$축 방향으로 $-4$만큼 평행이동]]했더니 [[touch|$x$축에 접한다]]. [[ask|상수 $a$의 값]]을 구하시오.",
  "steps": [{ "tex": "y=(x-1)^2+\\p{h}{a-1}", "concept_id": "c.perfect-square", "why": "…" }]
}
```

- **가리킬 구절은 `[[이름|구절]]`로 감싼다.** 지시 대상은 `problem/이름`이다. 수식 안의 부분은 `\p{이름}{…}`으로 표시하고 같은 방식(`problem/이름`)으로 가리킨다. 문제 전체는 `problem`. 구절은 한 줄에 들어갈 길이로 잡는다(줄이 바뀌지 않는다).
- **읽으면서 친 밑줄은 끝까지 둔다.** ① 읽기 문장에서 조건 구절에 `underline` + `until:"scene"`. 뒤에서 그 조건을 다시 말할 때는 `flash`나 `circle`로 짚는다.
- **풀이 줄에는 `highlight`를 쓰지 않는다.** 앞에 적은 줄이 흐려진다. 시험지에 적은 줄은 흐려지지 않는다. 줄을 짚을 때는 식의 부분(`step:1/h`)에 `underline`·`circle`. 줄 전체(`step:1`)에 밑줄을 치면 지면 폭 전체에 선이 그어지므로 쓰지 않는다.
- **줄의 `think` 칸은 화면에 나오지 않는다.** 생각은 음성이 말한다. `why`와 `concept_id`는 그대로 쓴다(줄 오른쪽의 "왜?", "모르겠어요").
- **암산 메모**: ②③에서 말하는 암산 식은 듣기만 해서는 떠올리기 어렵다. 오른쪽 여백에 손글씨로 잠깐 띄우고 문장이 끝나면 지운다. `{"type":"handwrite","tex":"…","position":{"near":"problem","side":"right","gap":28},"align":"start","until":"sentence"}`. 한 문장에 하나, 18자 이내. 풀이 줄(종이에 적은 것)과 구분되도록 반드시 `until:"sentence"`로 둔다. 이 메모는 장면당 손글씨 4개 제한에서 빼고 센다.
- **남기는 여백 메모**는 숙련자가 실제로 적을 만한 것 하나둘만, 밑줄 친 구절 바로 아래에. `{"type":"handwrite","text":"→ 꼭짓점 높이 = 0","position":{"near":"problem/touch","side":"below","gap":4},"until":"scene"}`.

검사(`npm run lesson:check`)가 다음을 `STYLE`로 알려 준다: `worked-problem`(문제 칸 없음), `worked-scan`(첫 줄 전의 생각이 3분의 1 미만), `worked-tone`(해설자 말투), `worked-lookback`(답 뒤에 문제를 다시 보는 문장 없음), `worked-highlight`(풀이 줄 highlight).

기준 예는 `content/lessons/rm-22-w1.json`이다. 기존 `rm-11-w1`은 문제 장면(chain)과 풀이 장면이 나뉘어 있어 이 매뉴얼에 맞지 않으며, 다시 만들 대상이다.

## 2. 대본: 생각의 순서

장면 하나 안에서 다음 순서로 흐른다. 문장 수는 문제 길이에 따라 15~30개.

| 단계 | 무엇을 하는가 | 역할 |
|---|---|---|
| ① 읽기 | 문제를 읽는다. 읽으면서 걸리는 표현에 밑줄 | `say` |
| ② 훑기 | 식과 조건의 모양에서 눈에 띄는 것을 말한다 | `think` |
| ③ 암산 탐색 | 머릿속으로 식을 바꿔 본다. 해 본 것과 그 결과 | `think` |
| ④ 시작점 | 그래서 무엇부터 적을지 정한다 | `think` |
| ⑤ 줄 쓰기 | 한 줄 적고, 다음 줄로 넘어가는 이유를 말하고, 또 적는다 | `write` ↔ `think` |
| ⑥ 답과 올려다보기 | 답을 적고, 문제를 다시 보며 요구한 것이 맞는지 확인 | `write`, `think` |
| ⑦ 가져갈 것 | 이런 모양의 문제에서 처음 떠올릴 것 한두 문장 | `say` |

- `think`는 머릿속, `write`는 종이, `say`는 읽기와 마무리다. `write` 문장에서만 풀이 줄이 나타난다. `think` 동안 화면에는 새 줄이 생기지 않고, 밑줄·가리키기만 움직인다.
- ②~④가 이 강의의 핵심이다. **전체 문장의 3분의 1 이상**을 여기에 쓴다. 문제를 읽자마자 첫 줄을 적는 대본은 실패다.

### ②③④ 쓰는 법: 암산 탐색

숙련자가 실제로 머릿속에서 하는 일을 **구체적인 식과 수로** 말한다.

1. **무엇이 보이는가.** 식의 모양, 숫자의 관계, 조건의 표현. "일차항 계수가 짝수네요", "두 식에 $x-1$이 공통으로 들어 있습니다", "접한다는 말이 있습니다".
2. **머릿속으로 해 본 것.** 실제 변형을 말한다. "$x^2-2x$는 $(x-1)^2$에서 1만 빼면 됩니다." "인수분해가 되는지 곱해서 $-6$, 더해서 $1$인 두 수를 찾아보면 $3$과 $-2$."
3. **그래서 보이는 것.** 그 변형이 문제가 요구하는 것과 어떻게 이어지는지. "그러면 꼭짓점이 바로 보이고, 접하는 조건은 꼭짓점의 높이 하나로 끝날 것 같습니다."
4. **버린 길이 있으면 한 문장.** "판별식으로도 되지만 식을 한 번 더 세워야 해서, 꼭짓점으로 가겠습니다."
5. **첫 줄 결정.** "그러면 완전제곱식으로 고친 식부터 적겠습니다."

말투는 **추측하는 사람의 말투**다. 숙련자도 적기 전에는 확신하지 않는다.

- 쓴다: "~일 것 같습니다", "~가 나올 것 같네요", "~해 보면 ~이니까", "~부터 해 보겠습니다", "이건 ~로 가면 길어지겠네요".
- 쓰지 않는다: "이 문제는 ~유형입니다", "이 문제에는 번역할 곳이 두 군데 있습니다", "~를 이용해야 합니다" (답을 이미 아는 해설자의 말투).

개념은 **한 구절로 불러오기만** 한다. "접한다니까 판별식이 0", "아래로 볼록이니까 꼭짓점이 가장 낮은 곳". 개념의 정의나 이유를 두 문장 넘게 다시 설명하지 않는다. 그건 개념 강의의 일이고, 모르는 학습자는 줄의 "모르겠어요"로 개념 강의에 간다.

### ⑤ 쓰는 법: 줄에서 줄로

- **적기 전에 이유를 먼저 말한다.** 순서는 항상 `think`(왜 이 변형을 하는가) → `write`(적는다). 이유는 "목표까지 무엇이 남았는가"로 말한다. "이제 $a$만 남기면 됩니다", "$y$가 혼자 있어야 꼭짓점을 읽을 수 있으니 4를 넘깁니다".
- **암산으로 건너뛴 계산은 건너뛰었다고 말한다.** 숙련자는 모든 계산을 적지 않는다. "전개는 머릿속으로 하면 $x^2-2x+1$, 여기서 상수만 맞추면 됩니다." 적지 않은 계산도 한 구절로는 들려준다.
- **감각 검사를 넣는다.** 숙련자가 중간에 하는 짧은 확인. "부호가 반대로 들어갔는지만 한 번 봅니다", "$a$가 양수여야 하는데 맞네요". 줄마다 넣지 않고 실제로 틀리기 쉬운 곳에만.
- **`write` 문장은 적는 내용만.** 적으면서 개념을 설명하지 않는다.

### ⑥⑦ 쓰는 법

- 답을 적은 뒤 **문제를 다시 본다.** "구하라는 것이 $a$의 값이었죠. $a=5$, 맞습니다." 문제가 범위·조건을 요구했다면 그것도 여기서 확인한다.
- 마지막 한두 문장은 이 문제에서 가져갈 **시작 습관**이다. 풀이 요약이 아니다. "이차식을 보면 먼저 완전제곱식으로 고쳐지는지 암산해 보세요. 꼭짓점이 보이면 접한다, 만난다 같은 조건이 높이 비교로 바뀝니다."
- 다른 강의를 가리킬 때 음성에서는 번호 없이 단원명만 말한다(`learning-studio-content-principles.md` 6-1).

### 예시: 같은 문제, 두 대본

문제: 이차함수 $y=x^2-2x+a$의 그래프를 $y$축 방향으로 $-4$만큼 평행이동했더니 $x$축에 접한다. 상수 $a$의 값은?

**맞지 않는 대본** (해설자가 개념을 차례로 설명한다)

> (think) 풀기 전에 머릿속에서 할 일은, 문제 문장 중에 수식으로 번역되는 말을 찾는 것입니다. 이 문제에는 두 군데 있습니다.
> (think) 먼저 평행이동입니다. 그래프를 $y$축 방향으로 $q$만큼 평행이동하면 관계식의 $y$ 자리에 $y-q$를 대입한다고 했죠. …
> (think) 다음은 "$x$축에 접한다"입니다. 접한다는 것은 포물선이 $x$축과 한 점에서만 만난다는 뜻입니다. …

**맞는 대본** (푸는 사람이 속으로 하는 말)

> (say) 문제를 읽겠습니다. … 이때 상수 $a$의 값을 구하라는 문제입니다.
> (think) 식부터 봅니다. $x^2-2x$, 일차항 계수가 $-2$네요. 이건 $(x-1)^2$에서 1만 빼면 되는 모양입니다.
> (think) 그러면 머릿속으로 $(x-1)^2+a-1$. 꼭짓점이 $x=1$에 있고 높이는 $a-1$입니다.
> (think) 이걸 아래로 4만큼 내리면 꼭짓점 높이가 $a-5$가 되겠죠. 아래로 볼록인 포물선이 $x$축에 접하려면 꼭짓점이 정확히 $x$축 위에 놓여야 하니, $a-5$가 0. 답은 5가 나올 것 같습니다.
> (think) 판별식으로도 풀 수 있지만 옮긴 식을 한 번 더 세워야 합니다. 꼭짓점으로 가는 쪽이 짧겠네요. 완전제곱식으로 고친 식부터 적겠습니다.
> (write) $y=(x-1)^2+a-1$.
> (think) 이제 4만큼 내립니다. 꼭짓점의 높이만 바뀝니다.
> (write) $y=(x-1)^2+a-5$.
> …

앞의 대본은 틀린 말이 없지만 "잘 푸는 사람의 생각"이 아니라 "풀이의 해설"이다. 뒤의 대본은 식을 보고 암산으로 바꿔 본 뒤 길을 고른다.

## 3. 풀이 데이터에서 대본으로

풀이 가공 데이터(`pdf-to-data/data/standard/BRIEF_SOLUTION.md`)의 칸은 대본의 다음 자리로 간다.

| 데이터 | 대본에서 |
|---|---|
| `entry.scan[]` (보이는 것, 해 본 암산, 결과) | ②③ 훑기와 암산 탐색의 `think` 문장. 순서와 수치를 그대로 |
| `entry.rejected[]` | ③의 "버린 길" 한 문장 |
| `entry.plan` | ④ 시작점 결정 문장 |
| `entry.triggers[]` | ① 읽기 때의 밑줄과 여백 메모(`phrase` → 손글씨 `means`). **음성으로 번역 목록을 나열하지 않는다** |
| `lines[].aim` | ⑤ 그 줄을 적기 직전의 `think` 문장 |
| `lines[].tex` | `steps[].tex`와 `write` 문장 |
| `lines[].why`, `concept_ids` | `steps[].why`, `steps[].concept_id` ("모르겠어요" 되짚기). 음성으로는 한 구절만 |
| `lines[].mental` | 적지 않고 말로만 지나가는 계산. ⑤의 "암산으로 건너뛴 계산" |
| `lines[].pitfall` | ⑤의 감각 검사 문장. 실제로 자주 틀리는 곳만 |
| `entry.pattern_note` | ⑦ 가져갈 것 |

숙련자의 길이 원본 풀이의 길과 다를 수 있다(위 예시에서 원본은 판별식, 숙련자는 꼭짓점). 이때는 **숙련자의 길을 주 풀이로** 하고, 원본의 길은 "버린 길"이나 변형 문제 해설에서 언급한다. 어느 길이 숙련자의 길인지는 대본 작성자가 정하지 말고 풀이 데이터에서 정해 온다(대표 검수 대상).

## 4. 검수 체크리스트

제작 뒤, 음성을 만들기 전에 대조한다.

- [ ] 문제가 풀이 내내 화면 위에 보이는가. 문제를 가리는 장면 전환이 없는가.
- [ ] 풀이 줄이 위에서 아래로 한 줄씩, `write` 문장과 함께 나타나는가.
- [ ] 첫 `write` 전에 `think`가 전체의 3분의 1 이상인가.
- [ ] 암산 탐색에 실제 식과 수가 들어 있는가("식을 살펴보면" 같은 말만 있고 내용이 없지 않은가).
- [ ] 추측의 말투인가. "이 문제는 ~유형", "~를 이용해야 합니다"가 없는가.
- [ ] 개념을 두 문장 넘게 다시 설명한 곳이 없는가.
- [ ] 모든 줄 앞에 "왜 지금 이 변형인가"가 있는가.
- [ ] 답을 적은 뒤 문제를 다시 보는 문장이 있는가.
- [ ] 마지막 문장이 풀이 요약이 아니라 시작 습관인가.
- [ ] 화면에 숙련자가 시험지에 하지 않을 것(표, 흐름도, 정밀 그래프)이 없는가.
- [ ] `lesson:check`의 `STYLE worked-*` 경고가 0건인가.
- [ ] 1600×860과 390×844에서 문제가 끝까지 위에 보이는가.
