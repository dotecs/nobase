# 문제풀이 강의 제작 매뉴얼 (v1.1, 2026-11-13 대표 기획 의도)

개념 강의는 `learning-studio-lesson-production-manual.md`를 따른다. 이 문서는 `kind:"worked"` 강의에만 적용하고, 두 문서가 다르면 문제풀이 강의에서는 이 문서가 우선한다. 지시(chalk)·TTS·자막·모바일 규칙은 개념 강의 매뉴얼 3·4·8·9장을 그대로 쓴다.

## 0. 한 문장으로

> **이 문제를 잘 푸는 사람은, 풀면서 무슨 생각을 하는가**를 보여 준다.

개념을 다시 가르치는 강의가 아니다. 학습자는 숙련자의 시험지를 어깨 너머로 보면서, 그 사람이 속으로 하는 말을 듣는다. 화면은 **시험지**, 음성은 **그 사람의 머릿속**이다.

가장 중요한 부분은 **줄과 줄 사이**다. 원본 풀이에는 적은 줄만 있고, 왜 그 줄부터 적었는지, 왜 다음에 그 줄이 오는지는 적혀 있지 않다. 이 강의가 존재하는 이유는 그 적히지 않은 부분을 말로 꺼내 주는 것이다. 구조는 `문제에 들어가며 하는 생각 → 첫 줄 → 다음 줄로 넘어가는 근거 → 다음 줄 → …`이다(2장).

## 1. 화면: 시험지 지면

시험지에서 문제를 푸는 모습과 같아야 한다.

1. **문제는 화면 맨 위에 처음부터 끝까지 나와 있다.** 풀이가 진행되는 동안 사라지거나 다른 화면으로 바뀌지 않는다. 숙련자는 풀다가 문제를 다시 올려다본다. 학습자도 그럴 수 있어야 한다.
2. **풀이는 문제 아래로 한 줄씩 적혀 내려간다.** 위에서 아래로만 쌓인다. 지나간 줄은 지우거나 접지 않는다.
3. **마지막 줄은 답이다.** 답을 적고 표시한다(∴, 밑줄). 답이 문제가 요구한 꼴(값, 범위, 식)인지는 3장의 "올려다보기"에서 말로 확인한다.
4. **여백 메모는 실제로 시험지에 할 만한 것만.** 문제 문장의 표현에 밑줄, 그 옆의 짧은 손글씨(`→ D=0`), 약식 그래프. 숙련자가 시험지에 하지 않을 것(개념 정리 표, 공식 모음, 번역 흐름도)은 올리지 않는다.
5. **그림은 여백의 약식 그림 수준으로.** 그래프나 수직선이 풀이의 일부일 때(부등식의 해 읽기 등)만 풀이 옆이나 아래에 그린다. 축 눈금까지 정확한 그래프는 숙련자가 그리지 않으므로 쓰지 않는다. 답을 확인하는 정밀한 그래프가 필요하면 풀이가 끝난 뒤의 장면에 둔다.

### 금지

- 문제를 보여 주는 장면과 풀이 장면을 따로 두는 것. 장면이 넘어가면 문제가 사라진다.
- 풀이 전에 "번역 흐름도"(chain)나 개념 정리를 한 화면 가득 보여 주는 것.
- 풀이 줄을 한꺼번에 보여 주는 것. 줄은 말과 함께 한 줄씩 나타난다.

### 무대 구성

풀이 전체를 **한 장면**에 둔다(문제 읽기부터 답까지). 장면을 나누면 지면이 끊긴다. 풀이 뒤에 붙는 장면은 변형 문제(quiz) 하나뿐이고, 정밀 그래프로 답을 확인할 필요가 있을 때만 그 앞에 확인 장면을 하나 더 둔다.

| 지면 요소 | 무대에서 |
|---|---|
| 문제 | `steps` 무대의 `problem` (맨 위 고정) |
| 풀이 줄 | `steps` 무대의 `steps[]`, 문장의 `cue.step`으로 한 줄씩 |
| 여백 메모·밑줄 | `items`(손글씨) + `draw`/`label` 지시 |
| 답 표시 | 마지막 줄의 답 부분(`\p{ans}{…}`)에 `underline`, `until:"scene"` |
| 암산으로 스쳐 가는 식 | 오른쪽 여백의 손글씨, `until:"sentence"` (아래 "암산 메모") |

### 문제 칸 쓰는 법 (2026-11-13 추가)

`steps` 무대에 `problem`을 적으면 문제가 풀이 줄 위에 장면 내내 고정된다. 아직 적지 않은 줄의 자리는 처음부터 비워 두므로, 줄이 늘어나도 문제와 앞줄이 움직이지 않는다. 세로 화면(모바일)에서는 문제가 위에 붙어 있고 풀이만 스크롤된다.

```json
"stage": {
  "type": "steps",
  "problem": "이차함수 $y=\\p{q}{x^2-2x}+a$ 의 그래프를 [[move|$y$축 방향으로 $-4$만큼 평행이동]]했더니 [[touch|$x$축에 접한다]]. [[ask|상수 $a$의 값]]을 구하시오.",
  "steps": [{ "tex": "y=(x-1)^2+\\p{h}{a-1}", "concept_id": "c.perfect-square", "why": "…" }]
}
```

- **가리킬 구절은 `[[이름|구절]]`로 감싼다.** 지시 대상은 `problem/이름`이다. 수식 안의 부분은 `\p{이름}{…}`으로 표시하고 같은 방식(`problem/이름`)으로 가리킨다. 문제 전체는 `problem`. 구절은 한 줄에 들어갈 길이로 잡는다(줄이 바뀌지 않는다).
- **읽으면서 친 밑줄은 끝까지 둔다.** ① 읽기 문장에서 조건 구절에 `underline` + `until:"scene"`. 뒤에서 그 조건을 다시 말할 때는 `flash`나 `circle`로 짚는다.
- **풀이 줄에는 `highlight`를 쓰지 않는다.** 앞에 적은 줄이 흐려진다. 시험지에 적은 줄은 흐려지지 않는다. 줄을 짚을 때는 식의 부분(`step:1/h`)에 `underline`·`circle`. 줄 전체(`step:1`)에 밑줄을 치면 지면 폭 전체에 선이 그어지므로 쓰지 않는다.
- **줄의 `think` 칸은 화면에 나오지 않는다.** 생각은 음성이 말한다. `why`와 `concept_id`는 그대로 쓴다(줄 오른쪽의 "왜?", "모르겠어요").
- **암산 메모**: 근거 문장에서 말하지만 줄로 적지 않는 식(대입할 식, 쓸 공식)은 듣기만 해서는 떠올리기 어렵다. 오른쪽 여백에 손글씨로 잠깐 띄우고 문장이 끝나면 지운다. `{"type":"handwrite","tex":"…","position":{"near":"problem","side":"right","gap":28},"align":"start","until":"sentence"}`. 한 문장에 하나, 18자 이내. 풀이 줄(종이에 적은 것)과 구분되도록 반드시 `until:"sentence"`로 둔다. 이 메모는 장면당 손글씨 4개 제한에서 빼고 센다.
- **남기는 여백 메모**는 숙련자가 실제로 적을 만한 것 하나둘만, 밑줄 친 구절 바로 아래에. `{"type":"handwrite","text":"→ 꼭짓점 높이 = 0","position":{"near":"problem/touch","side":"below","gap":4},"until":"scene"}`.

검사(`npm run lesson:check`)가 다음을 `STYLE`로 알려 준다: `worked-problem`(문제 칸 없음), `worked-scan`(첫 줄 전에 문제에 들어가며 하는 생각이 없음), `worked-reason`(줄을 연달아 적음), `worked-acting`(연기 지시어·"~네요" 투), `worked-tone`(풀이를 밖에서 분류하는 말), `worked-lookback`(답 뒤에 문제를 다시 보는 문장 없음), `worked-highlight`(풀이 줄 highlight).

기준 예는 `content/lessons/rm-22-w1.json`이다. 기존 `rm-11-w1`은 문제 장면(chain)과 풀이 장면이 나뉘어 있어 이 매뉴얼에 맞지 않으며, 다시 만들 대상이다.

## 2. 대본: 생각 → 줄 → 근거 → 줄 (2026-11-13 대표 정정)

장면 하나 안에서 다음 구조로 흐른다. 문장 수는 줄 수의 약 3배(15~25개).

| 순서 | 무엇을 하는가 | 역할 |
|---|---|---|
| ① 읽기 | 문제를 읽는다. 조건 구절에 밑줄 | `say` |
| ② 문제에 들어가며 하는 생각 | 조건이 무엇이고, 그래서 무엇부터 적는지 | `think` |
| ③ 첫 줄 | 첫 줄을 적는다 | `write` |
| ④ 다음 줄로 넘어가는 근거 | 왜 그다음에 이 줄이 오는지 | `think` |
| ⑤ 다음 줄 | 적는다 | `write` |
| … | ④⑤를 답까지 반복 | `think` ↔ `write` |
| ⑥ 답 확인 | 문제가 구하라고 한 것과 답을 맞춰 본다 | `think` |
| ⑦ 가져갈 것 | 이런 조건이 나오면 무엇부터 하는지 한두 문장 | `say` |

- **`write` 앞에는 반드시 `think`가 온다.** 줄을 연달아 적지 않는다. 줄과 줄 사이의 `think`가 이 강의의 본체다.
- `write` 문장은 적는 식만 읽는다. 설명을 섞지 않는다.
- `think` 동안 화면에는 새 줄이 생기지 않고, 밑줄·가리키기와 잠깐 뜨는 메모만 움직인다.

### 풀이의 길은 원본 풀이를 따른다

줄의 순서와 방법은 **교재 원본 풀이의 길**을 따른다. 더 짧은 다른 길이 보여도 대본 작성자가 길을 바꾸지 않는다(대표 지시가 있을 때만 바꾼다). 다른 길은 넣지 않거나, 넣더라도 변형 문제 해설에 한 줄로만 둔다.

> 정정 사례(rm-22-w1): 처음에는 "완전제곱식으로 고쳐 꼭짓점의 높이로 푸는 길"로 썼다가, 원본대로 "옮긴 식을 구한다 → $y=0$과의 교점 방정식 → 판별식 0"으로 되돌렸다.

### ② 문제에 들어가며 하는 생각

첫 줄을 적기 전에, 푸는 사람이 문제를 읽고 정리하는 것을 2~4문장으로 말한다.

1. **조건이 무엇인가.** "조건은 두 가지입니다. 그래프를 평행이동했다는 것, 그리고 옮긴 그래프가 $x$축에 접한다는 것입니다."
2. **조건 사이의 순서.** "접한다는 것은 옮긴 뒤의 그래프에 대한 조건입니다."
3. **그래서 무엇부터 적는가.** "그래서 평행이동한 그래프의 관계식부터 구합니다."
4. 첫 줄에 필요한 변형이 있으면 그것까지. "$y$ 자리에 $y+4$를 넣습니다."

조건 구절을 말할 때마다 문제 문장의 그 구절을 짚는다(`flash`).

### ④ 다음 줄로 넘어가는 근거

앞줄에서 다음 줄이 **왜** 나오는지를 말한다. 근거는 세 가지 중 하나다.

- **문제의 조건을 쓴다.** "이제 접한다는 조건을 씁니다. $x$축은 $y=0$인 직선이고, 접한다는 것은 이 직선과 포물선의 교점이 한 개라는 뜻입니다."
- **목표까지 남은 것.** "$y$만 남도록 4를 우변으로 넘깁니다."
- **쓸 도구를 고른 이유.** "이차방정식이므로 판별식이 0이면 됩니다. 일차항의 계수가 짝수이므로 $\frac D4$를 씁니다."

근거가 두 단계면 문장을 둘로 나눈다(조건의 뜻 → 그래서 세우는 식). 틀리기 쉬운 곳(부호, 괄호)은 근거 문장에서 한 구절로 짚는다. 개념의 정의나 이유를 두 문장 넘게 다시 설명하지 않는다. 모르는 학습자는 줄의 "모르겠어요"로 개념 강의에 간다.

근거에서 말하는 식 가운데 줄로 적지 않는 것(대입할 식, 쓸 공식)은 오른쪽 여백에 잠깐 띄운다(1장의 "암산 메모").

### 말투: 담담하게, 연기하지 않는다

`think`는 생각의 **내용**을 말하는 것이지, 생각하는 **모습**을 연기하는 것이 아니다.

- 쓰지 않는다: `[thinking aloud]` 같은 감정·연기 지시어, "~네요", "~것 같네요", "~겠죠", "~일 것 같습니다", 혼잣말 투.
- 쓴다: 평서문. "~입니다", "~합니다", "~이므로 ~를 씁니다".
- TTS 지시어는 도입 `[warm, steady lecture tone]`, 호흡 `[short pause]`, 맺음 `[concluding, relaxed]`만 쓴다. `think`와 `write` 문장에는 지시어를 붙이지 않는다.
- "이 문제는 ~유형입니다"처럼 풀이를 밖에서 분류하는 말은 쓰지 않는다.

### ⑥⑦ 쓰는 법

- 답을 적은 뒤 문제가 구하라고 한 것을 다시 짚는다. "구하라는 것은 상수 $a$의 값이었습니다. $a=5$입니다." 문제가 범위·조건을 요구했다면 여기서 확인한다.
- 마지막 한두 문장은 다음에 같은 조건을 만났을 때 **무엇부터 하는지**다. 풀이 요약이 아니다. "그래프가 $x$축에 접한다는 조건이 나오면, $y$ 자리에 0을 넣은 이차방정식의 판별식을 0으로 놓습니다."
- 다른 강의를 가리킬 때 음성에서는 번호 없이 단원명만 말한다(`learning-studio-content-principles.md` 6-1).
- 근은 개수가 아니라 종류로 말한다(개념 강의 매뉴얼 1장). 교점은 "한 개"라고 해도 되지만, 근은 "서로 같은 두 실근(중근)"이라고 한다.

### 예시: rm-22-w1의 흐름

문제: 이차함수 $y=x^2-2x+a$의 그래프를 $y$축 방향으로 $-4$만큼 평행이동했더니 $x$축에 접한다. 상수 $a$의 값은?

> (say) 문제를 읽겠습니다. …
> (think) 조건은 두 가지입니다. 그래프를 평행이동했다는 것, 그리고 옮긴 그래프가 $x$축에 접한다는 것입니다.
> (think) 접한다는 것은 옮긴 뒤의 그래프에 대한 조건입니다. 그래서 평행이동한 그래프의 관계식부터 구합니다.
> (think) $y$축 방향으로 $-4$만큼 평행이동하면, 관계식의 $y$ 자리에 $y+4$를 넣습니다.
> (write) $y+4=x^2-2x+a$.
> (think) $y$만 남도록 4를 우변으로 넘깁니다.
> (write) $y=x^2-2x+a-4$.
> (think) 이제 접한다는 조건을 씁니다. $x$축은 $y=0$인 직선이고, 접한다는 것은 이 직선과 포물선의 교점이 한 개라는 뜻입니다.
> (think) 두 그래프의 교점을 구하는 방정식은 두 식을 같다고 놓은 것입니다. $y$ 자리에 0을 넣습니다.
> (write) $x^2-2x+a-4=0$.
> (think) 교점이 한 개이려면 두 근이 서로 같아야 합니다. 이차방정식이므로 판별식이 0이면 됩니다.
> (write) $\frac D4=(-1)^2-(a-4)=0$.
> …


## 3. 풀이 데이터에서 대본으로

풀이 가공 데이터(`pdf-to-data/data/standard/BRIEF_SOLUTION.md`)의 칸은 대본의 다음 자리로 간다.

| 데이터 | 대본에서 |
|---|---|
| `entry.scan[]` (조건에서 읽은 것) | ② 문제에 들어가며 하는 생각의 `think` 문장 |
| `entry.rejected[]` | 쓰지 않는다(필요하면 변형 문제 해설에 한 줄) |
| `entry.plan` | ②의 마지막 문장: 무엇부터 적는가 |
| `entry.triggers[]` | ① 읽기 때의 밑줄과 여백 메모(`phrase` → 손글씨 `means`). **음성으로 번역 목록을 나열하지 않는다** |
| `lines[].aim` | ④ 그 줄을 적기 직전의 근거 `think` 문장 |
| `lines[].tex` | `steps[].tex`와 `write` 문장 |
| `lines[].why`, `concept_ids` | `steps[].why`, `steps[].concept_id` ("모르겠어요" 되짚기). 음성으로는 한 구절만 |
| `lines[].mental` | 줄로 적지 않고 근거 문장에서 말로만 지나가는 계산(여백 메모) |
| `lines[].pitfall` | ④ 근거 문장 안의 한 구절. 실제로 자주 틀리는 곳만 |
| `entry.pattern_note` | ⑦ 가져갈 것 |

풀이의 길은 원본 풀이를 따른다(2장). 풀이 데이터의 `lines`도 원본의 길로 적고, 다른 길은 `rejected`에만 둔다.

## 4. 검수 체크리스트

제작 뒤, 음성을 만들기 전에 대조한다.

- [ ] 문제가 풀이 내내 화면 위에 보이는가. 문제를 가리는 장면 전환이 없는가.
- [ ] 풀이 줄이 위에서 아래로 한 줄씩, `write` 문장과 함께 나타나는가.
- [ ] 첫 줄 전에 "조건이 무엇이고 무엇부터 적는지"가 있는가.
- [ ] 줄의 순서와 방법이 원본 풀이의 길과 같은가.
- [ ] 담담한 평서문인가. `[thinking aloud]`, "~네요", "~것 같습니다", "이 문제는 ~유형"이 없는가.
- [ ] 개념을 두 문장 넘게 다시 설명한 곳이 없는가.
- [ ] 모든 줄 앞에 "왜 다음에 이 줄인가"가 있는가. 줄을 연달아 적은 곳이 없는가.
- [ ] 답을 적은 뒤 문제를 다시 보는 문장이 있는가.
- [ ] 마지막 문장이 풀이 요약이 아니라 "이런 조건이 나오면 무엇부터 하는가"인가.
- [ ] 화면에 숙련자가 시험지에 하지 않을 것(표, 흐름도, 정밀 그래프)이 없는가.
- [ ] `lesson:check`의 `STYLE worked-*` 경고가 0건인가.
- [ ] 1600×860과 390×844에서 문제가 끝까지 위에 보이는가.
