## 1. 페이지 목표 · 방문자 · 주요 행동 · 섹션 순서

1. **1차 행동**: 플랜·가격 페이지(`/courses/n-training/pricing`)로 이동 → 스마트스토어 결제

## 부록 A. 1:1 실시간 강의 예약 페이지 `/booking` — 1차 빈 페이지 사양 (10-21 추가)

예약 기능 자체는 **별도 명세**로 설계한다(시간대·정원·플랜별 잔여 시간·Zoom 링크 발급 등 결정 필요). 이번 단계는 **경로와 접근 제어만** 만든다.

| 항목 | 사양 |
|---|---|
| 경로 | `app/(main)/booking/page.tsx` → `/booking` |
| 접근 | 로그인 필수. `lib/supabase-middleware.ts`의 `protectedPrefixes`에 `'/booking'` 추가 (비로그인 → `/login?returnTo=/booking`) |
| 권한 표시 | 로그인 사용자의 `active` 등록 기수 제목에 `STANDARD` 또는 `PREMIUM`이 포함되면 "예약 대상", 아니면 "현재 플랜에는 1:1 실시간 강의가 포함되어 있지 않습니다" 안내 + `/courses/n-training/pricing` 링크. 판정은 `lib/pricing.ts`의 제목 키워드 매칭 재사용 |
| 화면 | 공통 `Header` + 제목 `1:1 실시간 강의 예약` + 상태 문구 `예약 기능을 준비하고 있습니다. 준비되면 이 페이지에서 바로 예약할 수 있습니다.` + 보조 안내 **확정(10-22)**: `그때까지 예약은 톡톡 문의로 요청해 주세요.` + 톡톡 버튼(`https://talk.naver.com/w4jod1`, 새 탭, `content/contact.ts` 재사용) + `대시보드로 돌아가기` |
| 대시보드 연결 | `app/(main)/dashboard/page.tsx`에 예약 대상 사용자에게만 `1:1 예약` 버튼 노출 → `/booking`. 이 한 곳만 수정 |
| robots | `app/robots.ts` Disallow에 `/booking` 추가 |
| 금지 | 예약 폼·달력·시간 슬롯을 임시로 만들지 않는다. 빈 페이지 상태에서 "예약 완료" 같은 상태를 보여주지 않는다 |
| 완료 조건 | 비로그인 `/booking` → 로그인 이동. 베이직 수강생 → 안내+가격 링크. 스탠다드/프리미엄 수강생 → 준비 중 문구. `tsc`·`build` 통과 |
